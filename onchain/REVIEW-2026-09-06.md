## 4. Code findings

Severity follows the Immunefi-aligned scheme used in `BUG_BOUNTY.md`. "Patched" means the
fix is in this commit with a regression test under `test/review/`.

### R-01 · HIGH — Staking pays rewards out of other stakers' principal *(patched)*

`CCMStaking.sol`, `CCMSandboxStaking.sol`. `poolRemaining` is pure bookkeeping set in the
constructor; the physical reward source is the contract's ERC-20 balance, which also holds
every staker's deposit. Nothing checks that the pool was ever funded, so with an unfunded or
under-funded pool `_harvest` pays a claimant from other users' stakes and the last unstaker's
`safeTransfer` reverts.

Reproduction (`test/review/Staking.principal.test.ts`, RED before patch): two users stake
1,000 CCM each into an unfunded pool; after 30 days user A's `claim()` received
`100.000077 CCM` — taken from user B.

Fix: `availableRewards() = balanceOf(this) − totalStaked`; `pendingReward` is capped to it,
`recoverPoolRemainder` transfers at most the funded surplus. Yield is unchanged whenever the
pool is funded (second test proves it). Behavioural note: an under-funded period forfeits the
unpaid remainder (the accrual clock still advances) — document that the pool must be funded
before opening.

### R-02 · MEDIUM — A reverting oracle locks all staked principal *(patched)*

Every `stake` / `unstake` / `claim` path calls `priceOracle.getPrice()` through
`currentYieldRateBps`. If the oracle contract reverts (bricked, self-destructed, wrong
interface after `updateOracle`), withdrawals revert until the admin swaps it — on mainnet
that is a 48 h timelock. Fix: `_oraclePrice()` wraps the call in `try/catch` and yields a 0%
rate on failure. Test: oracle set to revert → `currentYieldRateBps() == 0`, `claim` and
`unstake` succeed, full principal returned.

### R-03 · MEDIUM — `migrateWithPermit` can be griefed by permit front-running *(patched)*

`CCMMigration.sol`. The permit was called unconditionally; anyone can lift the signature from
the mempool and submit `permit` first, after which the user's transaction reverts on the
consumed nonce. Fix: `try permit … catch {}` followed by an explicit allowance check (the
OpenZeppelin-recommended pattern). Test: a third party submits the permit, the user's
`migrateWithPermit` still emits `Migrated`.

### R-04 · MEDIUM — Unsold round CCM is stranded forever *(patched)*

`CCMTGESale.sol`. Rounds are pre-funded with `hardCapTokens` but there was no path to recover
the unsold remainder; an under-subscribed round locks CCM permanently. Fix:
`withdrawUnsoldCCM(roundId, to)` (ADMIN, `nonReentrant`), allowed only when the round is
closed or past `endTime`, transfers `hardCap − sold` once and shrinks the cap to `sold` so
buyers' allocations are untouched. Tests cover: refused while open, exact amount and
idempotence, buyers still claim 100 %, admin-only.

### R-05 · LOW — Stale sandbox test *(patched)*

`test/sandbox/CCMSandboxNFT.test.ts` still asserted a 1 h cooldown after `5fc7344` changed
`MINT_COOLDOWN` to 5 minutes; the two `it()`s were failing on `main`. Constant updated.

### R-06 · MEDIUM — Vesting schedules can be created without backing tokens *(reported; mainnet-deployed)*

`CCMVesting.createSchedule/Batch` never checks `ccm.balanceOf(this)`. Schedules are
first-come-first-served against whatever balance exists; later beneficiaries' `release` reverts.
Same class as R-04 for `CCMTGESale.createRound`. Mitigation for the deployed contract is
procedural: fund before scheduling (the runbook already says so); a v2 should track
`committed − released ≤ balance`.
